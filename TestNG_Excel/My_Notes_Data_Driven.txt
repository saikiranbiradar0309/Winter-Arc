Data Driven Testing


01. Data-Driven Testing in Selenium
    - Data-Driven testing (DDT) is a testing approach where you separate test data from the script/code. 

    - Instead of writing the same Selenium test multiple times with different inputs, you write the test 
      once and run it with multiple sets of data. 
    

================================================================================================


02. Simple Example
    - Suppose you want to test a login page with different usernames and passwords.

    - Instead of writing:

      Test 1 → username: user1, password: pass1
      Test 2 → username: user2, password: pass2
      Test 3 → username: user3, password: pass3

    - You can store the data in an Excel file, CSV, JSON, database, or other data source:

      Username	        Password	        Expected Result
      user1	            pass1	            Login successful
      user2	            wrong123	        Invalid password
      user3	            pass3	            Login successful

    - Then Selenium executes the same test logic for every row.

03. What is Apache poi library?
    - Apache POI is a Java library used to read, write, and manipulate Microsoft Office files, especially Excel files.

    - In Selenium automation, Apache POI is commonly used to read test data from Excel and write test results back to Excel.




04. Why is it used in Selenium?
    - For example, suppose your login test data is stored in Excel:
      
      Username	        Password
      user1	            pass123
      user2	            pass456
    
    - Your Selenium script can use Apache POI to read each row and execute the login test with that data.

07. Java classes used with Apache POI to open and save the Excel file

    a. FileInputStream - Reading Excel File 
       - FileInputStream is a java I/O Class used to read bytes from a file.

       - In Apache POI, we commonly use it to open an existing Excel file:
         
         FileInputStream fis = new FileInputStream("TestData.xlsx");
         Workbook workbook = new XSSFWorkbook(fis);

       - Think 
            Excel File
                ↓
            FileInputStream
                ↓
            Apache POI Workbook
    


    b. FileOutputStream 
       - FileOutputStream is used to write bytes to a file 

       - With Apache POI, after modifying the workbook, we use it to save the changes:

       - FileOutputStream fos = new FileOutputStream("TestData.xlsx");
         workbook.write(fos);
       
       - Think:
         
         Apache POI Workbook
                    ↓
         FileOutputStream
                    ↓
         Excel File


    - FileInputStream is used to read/open an existing Excel file, 
      whereas FileOutputStream is used to write/save data into an Excel file. 
      Apache POI uses these Java I/O streams to read from and write to Excel workbooks.



08. Apache POI Classes 
    - For Selenium automation, the most important Apache POI classes are related to Excel files.

    - XSSFWorkbook: Represents the entire Excel workbook

    - XSSFSheet: Represents a worksheet 

    - XSSFRow: Represents a row

    - XSSFCell: Represents a cell

    
    - The Hierarchy:
      

      XSSFWorkbook
            ↓
      XSSFSheet
            ↓
      XSSFRow
            ↓
      XSSFCell

09. Reading Data from Excel 

    - Usually we store test data excel inside our project directory like inside test data.
    
    - We wont store it inside like Downloads or Documents etc 

    - Rows will count from 0 and Cells will count from 1


package Youtube;


import java.io.FileInputStream;
import java.io.IOException;

import org.apache.poi.xssf.usermodel.XSSFCell;
import org.apache.poi.xssf.usermodel.XSSFRow;
import org.apache.poi.xssf.usermodel.XSSFSheet;
import org.apache.poi.xssf.usermodel.XSSFWorkbook;

public class ReadingDataFromExcel {

	public static void main(String[] args) throws IOException {
		
		
		FileInputStream fis = new FileInputStream("/Users/saikiranbiradar/Reminders/TestNG_Excel/testdata/Book 5.xlsx");
		
		XSSFWorkbook workbook = new XSSFWorkbook(fis);
		
		XSSFSheet sheet = workbook.getSheet("Book_Indent");  	// Preferred
		//XSSFSheet sheet = workbook.getSheetAt(0);  // Index value 
		
		
		// FInd out No.of Rows 
		int totalRows = sheet.getLastRowNum();
		
		System.out.println("Number of Rows: " + totalRows);
		
		
		
		// FInd out No.of Cells 
		int totalCells = sheet.getRow(1).getLastCellNum();
		
		System.out.println("Number of Cells: " +totalCells);
		
		
		for(int rows=0; rows<=totalRows; rows++)
		{
			XSSFRow currentRow = sheet.getRow(rows);
			
			for(int cells=0; cells<totalCells; cells++)
			{
				XSSFCell cell = currentRow.getCell(cells);
				System.out.print(cell.toString() +"\t");
			}
			
			System.out.println();
		}
		
		
		workbook.close();
		
		fis.close();
		

	}

}

11. Writing Data Dynamically into Excel

package Youtube;

import java.io.FileOutputStream;
import java.io.IOException;
import java.util.Scanner;

import org.apache.poi.xssf.usermodel.XSSFCell;
import org.apache.poi.xssf.usermodel.XSSFRow;
import org.apache.poi.xssf.usermodel.XSSFSheet;
import org.apache.poi.xssf.usermodel.XSSFWorkbook;

public class WritingDynamicDataIntoExcel {

	public static void main(String[] args) throws IOException {
		
		FileOutputStream fos = new FileOutputStream("/Users/saikiranbiradar/Reminders/TestNG_Excel/testdata/Dynamic_Indent.xlsx");
		
		XSSFWorkbook workbook = new XSSFWorkbook();
		
		XSSFSheet sheet = workbook.createSheet("Dynamic_Data");
		
			
		
		// Dynamic Data
		Scanner sc = new Scanner(System.in);
		
		
		System.out.println("Enter Number of Rows you want to have");
		int numberOfRows = sc.nextInt();
		
		
		
		System.out.println("Enter Number of Cells you want to have");
		int numberOfCells = sc.nextInt();

		
		
		for(int rows=0; rows<=numberOfRows; rows++ )
		{
			
			XSSFRow currentRow = sheet.createRow(rows);
			
			for(int cells=0; cells<numberOfCells; cells++)
			{
				XSSFCell currentCell = currentRow.createCell(cells);
				
				currentCell.setCellValue(sc.next());
			}
		}
		
		
		workbook.write(fos);
		
		workbook.close();
		
		fos.close();
		
		
		System.out.println("File is Created");
		
	}

}

12. Utility File or Class
    - In a Selenium automation framework, a Utility file/class is a reusable class that contains 
      common methods that are needed in multiple test cases.
    
    - It helps you avoid writing the same code again and again.



Simple Example: 
    - Suppose you have 50 test cases and all of them need to read data from Excel.

    - Without a utility class, you might write:
      
      FileInputStream fis = new FileInputStream("TestData.xlsx");
      XSSFWorkbook workbook = new XSSFWorkbook(fis);
      XSSFSheet sheet = workbook.getSheet("Data");

    - In many test classes.

    - Instead, you create an ExcelUtility class.



Why do we use utility classes?
    a. Reusability: Write the code once and use it in many test cases.

    b. Avoid code duplication: Instead of repeating in every test, keep it inside one utility class.

    c. Easy Maintenance: Suppose tomorrow you change your Excel-reading logic.
            Without utility:

            100 test cases
                    ↓
            Change code in 100 places ❌
            

            With utility:
            
            ExcelUtility
                    ↓
            Change code in ONE place ✅
                    ↓
            All test cases use updated logic


    d. Cleaner test cases: Your test should focus on testing the application, not on handling Excel files.



For example:

a. ExcelUtility → Read/write Excel

b. ScreenshotUtility → Take screenshots

c. WaitUtility → Explicit waits

d. BrowserUtility → Browser-related common operations

e. ConfigUtility → Read properties/configuration files

f. DateUtility → Date-related operations
